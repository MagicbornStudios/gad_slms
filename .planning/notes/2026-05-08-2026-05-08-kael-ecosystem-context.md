# Kael is the ecosystem-builder that consumes our adapters

Operator note 2026-05-08: Kael is being used in the GAD ecosystem to build out UI / games / websites / etc. for everyone (including platform sites, Magicborn, Grime Time). Implication for slm-learning: our adapters need to be deployable via vLLM / Modal serve so Kael's runtime (and the broader GAD model gateway) can route to them. The current canonical 1.5B+hard+retain adapter (HE 64.0% / MBPP 64.0%) is the first non-7B model worth wiring into Kael's code-completion path. Track E (Kael computer-use traces) per slm-learning-101 is the formal lane — when we build that dataset, we should be able to feed Kael's actual interaction logs back as training data for a Kael-specialized adapter. Cross-references: slm-learning-101 (track E), slm-learning-121 (system-level MoE), slm-learning-124 (system-as-teacher).
