# Modal CLI on Windows: prepend PYTHONIOENCODING=utf-8 always

Modal's CLI prints a Unicode checkmark on success which crashes the cp1252 charmap encoder Windows uses by default. Without PYTHONIOENCODING=utf-8 set in the subprocess env, the CLI exits 0 BEFORE the Modal job is actually submitted (the app gets registered but 0 tasks queue). PowerShell's $env:PYTHONIOENCODING handles it; Bash subprocesses need the prefix in the same command line. Bit us twice 2026-05-08 — first PYTHONIOENCODING-less fire of 5 Modal training jobs registered ephemeral apps but submitted 0 tasks, second fire with 'PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -m modal run ...' worked. Candidate for promotion to a skill (modal-cli-windows-utf8-prefix). Refs: slm-learning-105, error msys-pathconv-translates-modal-volume-paths-2026-05-08.
